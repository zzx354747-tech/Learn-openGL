从这个项目里，最难的部分是 Framebuffer离屏渲染，这也是项目名字直接叫"Framebuffer Demo"的原因，说明你同学是把它作为核心攻克点来练习的。

为什么Framebuffer最难？

初学者对渲染的理解通常是：

"画东西 → 直接显示到屏幕"

但Framebuffer打破了这个直觉，变成：

"画东西 → 先渲染到一张纹理上 → 再把这张纹理贴到一个铺满屏幕的四边形 → 才显示"

这中间涉及几个容易出错的概念：

  • FBO/RBO的创建和绑定顺序不能错
  • 渲染目标的切换（绑定自定义FBO → 绑回默认FBO）时序问题
  • 窗口resize时纹理附件也要跟着重建（代码里的framebuffer->resize()就是在处理这个）
  • Screenquad的UV坐标如果写反，画面会上下颠倒

它难在哪里体现？

代码里能看到他专门处理了窗口大小变化的回调：

cpp
void framebuffer_size_callback(...) {
    if (framebuffer) framebuffer->resize(width, height);
}

这个细节很多教程都不提，但不处理的话窗口缩放就会画面错乱。能注意到这里说明理解得比较深。

第二难是CubeMap/Skybox，因为它需要同时理解：立方体贴图的采样方向、深度测试的trick（让天空盒永远在最远处）、以及去掉view矩阵位移分量的数学原因。
