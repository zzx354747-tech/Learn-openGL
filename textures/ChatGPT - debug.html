{

    glGenTextures(1, &depthCubeMap);

        depthCubeMap

    for (int i = 0; i < 6; i++)

        glTexImage2D(
            GL_TEXTURE_CUBE_MAP_POSITIVE_X + i,
            0,
            GL_DEPTH_COMPONENT,
            width,
            height,
            0,
            GL_DEPTH_COMPONENT,
            GL_FLOAT,
            nullptr
        );
    }

    glTexParameteri(
        GL_TEXTURE_CUBE_MAP,
        GL_TEXTURE_MIN_FILTER,
        GL_NEAREST
    );

    glTexParameteri(
        GL_TEXTURE_CUBE_MAP,
        GL_TEXTURE_MAG_FILTER,
        GL_NEAREST
    );

    glTexParameteri(
        GL_TEXTURE_CUBE_MAP,
        GL_TEXTURE_WRAP_S,
        GL_CLAMP_TO_EDGE
    );

    glTexParameteri(
        GL_TEXTURE_CUBE_MAP,
        GL_TEXTURE_WRAP_T,
        GL_CLAMP_TO_EDGE
    );

    glTexParameteri(
        GL_TEXTURE_CUBE_MAP,
        GL_TEXTURE_WRAP_R,
        GL_CLAMP_TO_EDGE

        fbo

这一句

C++

    GL_TEXTURE_CUBE_MAP,
    GL_TEXTURE_MIN_FILTER,
    GL_NEAREST

意思是：

当纹理被缩小时，用最近的那个 texel。

比如你的 cubemap 是：

C++
1024 x 1024

但是屏幕上某个区域只需要显示很小一块，很多 texel 会对应到一个片元，这就叫 minification，缩小采样。

参数1：GL_TEXTURE_CUBE_MAP

C++
GL_TEXTURE_CUBE_MAP

表示你正在设置的是一个 立方体贴图对象。

如果是普通2D阴影贴图，就会写：

C++
GL_TEXTURE_2D

但点光源阴影用的是：

C++
samplerCube

所以这里必须是：

C++
GL_TEXTURE_CUBE_MAP

参数2：GL_TEXTURE_MIN_FILTER

C++
GL_TEXTURE_MIN_FILTER

表示：

当纹理被缩小时，怎么采样。

也就是远处、小面积、多个纹素压缩到一个片元时怎么取值。

参数3：GL_NEAREST

C++
GL_NEAREST

表示：

直接取最近的那个纹素，不插值。

对于深度贴图来说，这很常见。

因为深度贴图存的不是颜色，而是：

C++
距离光源的深度值

例如：

0.31
0.32
0.89
0.90

如果你用线性插值：

C++
GL_LINEAR

它可能会把几个深度值混合起来，得到一个“中间深度”。

颜色贴图混合没问题，但深度比较时，混合深度有时会造成阴影边界判断不稳定。

所以初学阶段建议：

C++

MAG_FILTER

C++

    GL_TEXTURE_CUBE_MAP,
    GL_TEXTURE_MAG_FILTER,
    GL_NEAREST
);

这个和上面类似。

区别是：

C++
GL_TEXTURE_MAG_FILTER

表示：

当纹理被放大时，怎么采样。

比如 cubemap 只有：

C++
1024 x 1024

但某个阴影区域在屏幕上很大，一个 texel 被放大覆盖多个片元，这就叫 magnification，放大采样。

MIN 和 MAG 的区别

简单说：

MIN_FILTER：纹理被缩小时用
MAG_FILTER：纹理被放大时用

例如：

远处物体采样阴影图 -> 可能触发 MIN
近处物体采样阴影图 -> 可能触发 MAG

但你不需要手动判断。

GPU采样时会自动决定。

为什么点光源阴影通常用 GL_NEAREST？

因为阴影贴图的核心逻辑是：

glsl
currentDepth > closestDepth ? 在阴影中 : 不在阴影中

也就是比较：

当前片元到光源距离
和
shadow map 中记录的最近遮挡物距离

如果 depth cubemap 的值被线性插值了，closestDepth 就可能不再是真实某个遮挡物深度，而是几个深度的混合值。

所以基础版先用：

C++
GL_NEAREST

更可控。

以后你做 PCF 软阴影时，通常是在 shader 里自己采样周围多个方向，而不是完全依赖 GL_LINEAR。

5：边界模式 Wrap

这几句：

C++
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_CUBE_MAP, GL_TEXTURE_WRAP_R, GL_CLAMP_TO_EDGE);

控制的是：

如果采样坐标跑到边界附近，甚至超过范围，OpenGL怎么办？

普通2D纹理只有 S 和 T

普通纹理坐标是：

glsl
vec2 uv

也就是：

u, v

OpenGL里对应：

S, T

所以普通2D纹理一般写：

C++
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_REPEAT);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_REPEAT);

Cubemap 多一个 R

Cubemap 采样不是用：

glsl
vec2 TexCoords

而是用：

glsl
vec3 direction

例如：

glsl
texture(depthCubeMap, fragToLight);

这里的：

glsl
fragToLight

是一个三维方向：

x, y, z

所以 cubemap 有三个方向维度：

S, T, R

大致可以理解成：

S -> x方向
T -> y方向
R -> z方向

不是完全等同，但可以这样先理解。

参数1：GL_TEXTURE_CUBE_MAP

还是表示：

设置的是 cubemap 的参数。

参数2：GL_TEXTURE_WRAP_S

表示：

S方向越界时怎么处理。

参数2：GL_TEXTURE_WRAP_T

表示：

T方向越界时怎么处理。

参数2：GL_TEXTURE_WRAP_R

表示：

R方向越界时怎么处理。

Cubemap 必须考虑 R，因为它是通过三维方向采样的。

参数3：GL_CLAMP_TO_EDGE

C++
GL_CLAMP_TO_EDGE

意思是：

如果采样到了边界外，不重复纹理，不取黑边，而是固定取边缘处的值。

比如某个方向接近 cubemap 两个面之间的接缝。

如果不用：

C++
GL_CLAMP_TO_EDGE

可能会出现：

阴影边缘裂缝
cubemap 面之间有黑线
采样到错误边界

所以 cubemap 几乎固定用：

C++
GL_CLAMP_TO_EDGE

为什么不用 GL_REPEAT？

GL_REPEAT 的意思是：

超出范围后重复纹理。

普通地板贴图很适合：

C++
GL_REPEAT

因为你希望木地板一块一块重复。

但是阴影 cubemap 不适合。

因为 cubemap 的六个面代表的是六个真实方向：

+X -X +Y -Y +Z -Z

它不是一张可以无限重复的图片。

如果重复了，就相当于：

采样方向越界后，拿另一边错误的深度来判断阴影。

这会导致阴影错误。

为什么不用 GL_CLAMP_TO_BORDER？

方向光阴影的 2D shadow map 有时会用：

C++
GL_CLAMP_TO_BORDER

C++
float borderColor[] = {1.0, 1.0, 1.0, 1.0};

意思是 shadow map 外部默认“没有阴影”。

但 cubemap 通常不用这个。

因为 cubemap 本身覆盖完整球面方向，理论上没有普通2D阴影贴图那种“投影范围外”的问题。

所以点光源 cubemap 更常见的是：

C++
GL_CLAMP_TO_EDGE
